# Surface drop interrupted by ledge assist

A/D + S began a valid drop through the town floor, but automatic ledge assist
could catch that same floor a few frames later. PlayerController then cancelled
the active drop, and overlap recovery snapped the player back onto the surface.
The old input tests checked only the first update, so they passed despite the
later reversal. A full-controller trace reproduced y=677 -> 685.69 -> 677 while
moving right; the same failure occurred moving left, with S held or released.

The ledge candidate search excludes only the configured top-surface row while
that same row is marked by surfaceDropThroughRow. Other ledges retain their
normal capture behavior even during the drop. Clearing the existing drop state
restores normal capture on the top surface too. There is no global assist lock.
The S buffer also accepts Ctrl when the bound Run action is held and prevents
that gameplay Ctrl+S press from invoking the browser shortcut.

Validation:

- Expanded full-controller input regressions: 33 cases passed, including both
  directions, walking/running, held/released S, complete floor traversal,
  continued sideways velocity, collision clearance, and drop-state release.
  Before the fix, 12 combinations failed (4 re-grabs and 8 rejected Run chords).
- The ledge contract verifies the top-row exception, capture above and below
  that row during an active drop, and normal top-row capture after release.
- Jump/Flight, ledge-assist, running, natural-surface, and Worldroot contracts passed.
- Local headless Chrome, production PlayScene, canonical serve.py: all 8 real
  keyboard combinations descended from body y=6035 to y=6223 (depth 0 to 2),
  with no ledge capture, no solid overlap, and continued sideways movement.
  Running Ctrl+S events were accepted and default-prevented. No page errors.
- Syntax and scoped whitespace checks passed.
